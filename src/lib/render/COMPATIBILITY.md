# Drawing compatibility rendering

Both saved dialects use fixed-point document coordinates (`1 logical px = 8 units`) and are dispatched only from the saved tool descriptor.

- `multator` keeps toonop's original midpoint emitter and dot-as-filled-circle behavior.
- `toonio` ports `Tool.Curve` from the studied Tonio source: it consumes the duplicated endpoint sentinel, emits midpoint quadratics without re-running input preparation, and applies the `+0.01` coincident-point workaround.

Golden command tests are the geometry authority. Representative DPR=1 software-raster signatures guard broad pixel changes. Unlike original Tonio, toonop deliberately folds device pixel ratio into the Canvas transform; on DPR>1 this produces a sharper raster while logical geometry, widths, compositing, and path commands remain unchanged.

## Layers

A document frame is the composite of its visible layers, bottom-up (`schema_version: 3`, `layers[] → frames[] → strokes[]`, up to 20 layers, every layer the same length). Each layer rasterizes into its own transparent buffer before it lands on the target, so `eraser` and `contour-eraser` cut the alpha of their own layer only — the layer below shows through instead of the background. That is the single eraser path now: the former opaque "eraser paints the background color" branch is gone, so thumbnails, player, GIF and the WebP preview all erase the same way the canvas does. A `hidden` layer is skipped everywhere it could appear (canvas, timeline thumbnails, player, GIF, preview); a single-layer frame without erasers still draws straight into the target, pixel-identical to the composited path.

The shared fixture corpus is the parity contract between the TS and Rust validators, and both agree on every fixture. That includes number spelling: `1e2`, `100.0` and `100` are one JSON number, so both implementations canonicalize them to the same bytes and accept them alike — the editor cannot tell them apart after `JSON.parse`, and the server folds an integer-valued float back before its typed parse. The editor's own serializer never emits a float spelling anyway.

The format carries no layer name — the panel numbers rows by position, top-down. Older documents load through `v1 → v2 → v3`: a v2 document's frames become the cells of one visible layer, strokes and `tool_id`s untouched, and it renders exactly as it did before the migration.

Onion skin shows the neighbor cells of the **active layer** only, so a static background is not drawn twice. The `multator` active-frame alpha (0.8) applies to the whole composited frame, not per layer.

## Canvas viewport

Zoom (1–10, 0.5 per wheel notch) and pan live in `src/lib/ui/viewport.ts` as pure math over CSS pixels and reach the renderer through the optional `panX`/`panY` of `Viewport`: the layer buffers stay the size of the visible canvas, so a 10× zoom costs no extra memory. Thumbnails, player and export never pass a pan and render at 100%, unchanged. Panning is the middle button, space with a drag, or two fingers (pinch zooms too — the reference has no pinch, but the editor is mobile-first); a second finger never interrupts a stroke already under way. The Tonio threshold follows the reference's `_line.m / toonio.drawWindow.scale`: the zoom is frozen on `pointerdown` alongside the rest of the stroke settings, so mid-gesture zooming cannot change the geometry, and at zoom 1 the committed points are bit-identical to before.

## Tonio tools (schema v4)

`feather` and `pixel` join the tool table in `schema_version: 4`; v3 documents lift to it unchanged (the migration is the version bump). The feather is the pencil's midpoint curve filled with its second color before being stroked with the first (`tools.js` Feather.PostDraw), so its descriptor carries both. The pixel tool stores grid cells — `w * ~~(v / w)`, dedup against the cells the line already had, `Prepare` thinning by the tool width with no endpoint sentinel — and the renderer fills each cell as a square, Bresenham-filling the cells a fast drag skipped, so a `.toon` import of sparse cells draws right. Both are Tonio-dialect only, in the schema and in the toolbar.

The mega eraser is not a tool descriptor at all: like the reference it saves nothing, it cuts. `src/lib/tools/mega-eraser.ts` sweeps the gesture capsule (radius = width / 2) over the cell's strokes and rewrites the list with the surviving pieces, each keeping the descriptor of the stroke it came from. Unlike the reference, which lost that work for good, the cut is undoable: `EditorState.erases` keeps the previous stroke list and undo restores it once the cell is back in the state the cut left it.

## Importing `.toon`

`src/lib/format/toon-decode.ts` reads Tonio's binary files (v5 plus the legacy 1–4 shapes) into a document the editor's own validator accepts; `TOON_IMPORTER.md` has the layout and the decisions. Imported geometry is never re-prepared — the points in a file are already smoothed and thinned, so they go in as they are (×8 into fixed point) and render through the `toonio` dialect.

## Preset UX profiles

Beyond the stroke dialect, each toolbar preset owns a UX profile (`src/lib/ui/ux-profile.ts`). `multator` reproduces the reference editor end to end: black/red quick palette with the full picker and pipette behind `M`, white = eraser, adaptive `+`/`-` steps (1/5/10, cap 300), onion skin of the two previous frames only, active frame composited at 0.8 (its `containerSprite.alpha`), delete selects the previous frame, `Ctrl`+add inserts before, playback starts from frame 1 and returns to the edited frame, 5 fps default (30 fps stage ÷ 6). `toonio` reproduces the reference toonio.ru editor: the onion skin is built from the last three *visited* frames rather than the neighbors (`0.15 / history.length * (i + 1)`, bundle:426/437), the palette is the reference's 30-color grid capped at 50 (`defaultPalette`, `paletteLimit`), the pipette previews the color it would take in a 25px swatch throttled to 100 ms and its button opens the native `EyeDropper` on a second click, fps runs 1–30 (`editor.html:270`), the brush goes to 500 and the cursor grows a crosshair below 3 px and at 25 px and up (`tools.js` DrawCursor). One deliberate deviation: the reference toggles the onion on `Tab`, which is the only way a keyboard user leaves the canvas — we bind `K` instead. `toonop` keeps the editor's own behavior. The layers panel is a preset feature (`layers`): on in Toonop and Toonio, off in Multator; switching to a preset without the panel makes a hidden active layer visible again, since there would be no way back. Out of scope: the server save form and the contest `frameLimit`/`disableCopy` flags.

A profile also owns its `layout`. `bar` (Toonop, Multator) is the one panel under the canvas the editor always had; `toonio` gets `studio`, the reference's workplace (`editor.html`): tools in two columns on the left with undo/redo, full screen and the drafts list, canvas in the middle, palette box and brush box on the right, timeline and transport below. The brush box replaces the dotted widths with a 1–500 slider and two smoothing sliders (min. distance 0–30, smoothing 1–100), which is why smoothing left the "Configure panel" sheet. The transport adds first/previous/next/last frame, an fps slider with its number, and copy/paste frame. On a phone the side columns fold into rows above and below the canvas and the extreme-frame buttons and the fps slider drop out.

The palette box is the reference's `Palette`/`PalettePreview`: large outline and fill swatches with a label, a `+` and a swap between them, then a 35px gapless grid where the left button takes the outline and the right button the fill (`Enter` / `Shift+Enter` from the keyboard), the selected cell carrying a pencil/pen mark; picking a color off the eraser switches back to the pencil, and both the in-canvas pipette and the native `EyeDropper` drop what they take into the grid (`paletteAutoAdd`). Saved palettes live in `toon-editor:saved-palettes` with the reference's `toonio_saved_palettes` fields: a tile list of "Default" plus your own, save-current-under-a-name, and a preview offering load (confirmed), merge (reporting the colors that did not fit `PALETTE_LIMIT`) and delete. Edit mode deletes single colors or clears the grid behind a confirmation. Studio keys follow the reference: `A` frame, `Shift+A` layer, `Delete` frame, `Shift+Delete` layer, `J`/`L`, `←`/`→` across frames with wraparound, `↑`/`↓` across layers, `Alt+E` mega eraser, `F` the pen.

## Studio timeline

The `studio` layout also changes the timeline (reference `Timeline`, bundle:8645, `MouseDown` 8894). `bar` keeps the single strip of frame thumbnails; `studio` splits it into the shared layer list on the left — the same `LayerRows` the popup panel renders, so the two forms cannot drift, with the reference's row (eye, name, `⇕`, `×`, every control acting on its own row) under an «+ Слой» header rather than a footer; the drag ends on a window release, because reordering moves the handle's own node and drops its pointer capture — and a layer-by-frame grid of cell thumbnails on the right. The divider lives on the top edge of the bottom panel and resizes the *panel* (151px to 75vh, kept in the UI config as `panelHeight`). It is the reference's `#resizer` — a 16px band sitting `top: -8px`, half of it over the canvas, so the grab target is not the 1px border — and, as the reference does on `.draw`, the editor sets `user-select: none` so a resize never smears a selection across the chrome (the fields you type in keep theirs). The floor is the panel's own chrome plus a timeline showing exactly one layer row; further layers scroll. The timeline is the row that takes whatever height is left, so dragging the bar down hands the grid more layers and frames instead of spreading the buttons out. On a phone the stored height is ignored: the panel sizes itself to its contents, the timeline to its rows capped at 40vh, and the divider goes away. The studio does not also offer the layers popup, which would be a second copy of the same list, and add/delete frame sit on the transport after the frame keys, as on the reference bar, instead of beside the strip.

A click picks the cell's frame *and* layer. `Shift` spans the rectangle from the active cell to the clicked one, `Ctrl` adds or removes a single layer, and `Shift` with the arrows is the keyboard form of the Shift+click; `frame-selection.ts` holds that math. Four states share the grid, and each is a border shape rather than a colour, so none of them depends on hue (WCAG 1.4.1): the active cell a solid ring, the selection a dashed one, the copied block a dotted one, and onion frames a dotted underline under their number, with the copied block also marked `⧉` there.

`C` copies the selected cells with their relative offsets, `V` replaces the cells the buffer lands on from the active one, and `M` adds the buffer's strokes on top of what those cells already hold (`copyCells`/`replaceCells`/`mergeCells`). The block hangs from the active cell, which takes the buffer's first frame and its *top* layer: frames run forward, layers run downward the way the grid shows them, which is toward the lower indices the format stores them under. The target is clipped at the document edges, so a paste near the last frame writes what fits and one near the bottom layer keeps the buffer's top rows and drops what would fall off. `V` and `M` are both one undo step: the cells' previous contents go on a snapshot stack that also carries the mega-eraser cut, and undo restores the whole block as long as every cell is still exactly as the edit left it. In the `bar` layout there is no selection, so `C`/`V` stay whole-frame copy and paste and `M` stays Multator's palette toggle — its only way to the full color picker.

## Oldschool pen ("old" easter egg)

Typing `o`, `l`, `d` toggles the reference's hidden oldschool pen (Main.hx `lastThreeKeys` → DrawField.hx `onOldEndDraw`). The gesture is captured like a Multator line, but the commit runs Lang 5/5 px and traces a closed contour around the polyline at radius `trunc(size/2)` with a random wobble on gentle bends (`src/lib/tools/oldschool.ts`), stored under the v2 tool kinds `contour` (color) / `contour-eraser` (reference `action=4, size=0`). The renderer fills it as a closed midpoint multicurve (`emitMultatorClosedPath`, reference `multicurve(..., true)`); the eraser variant punches alpha. Tonio strokes ignore the flag. One deliberate fix over the port: a click without movement gives the 8-point circle the reference intended (its dot flag was never set).
