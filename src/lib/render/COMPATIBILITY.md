# Drawing compatibility rendering

Every stroke uses fixed-point document coordinates (`1 logical px = 8 units`) and is read only from the saved tool descriptor's `geometry`. The core has one reader per geometry and names no brush, editor or reference application:

- `line` — the points are a polyline.
- `smooth` — the points are the control points of a quadratic chain; each segment ends on the midpoint to the next point, and the last one lands on the last point.
- `cubic` — the control points are written out (`x0,y0, (c1x,c1y, c2x,c2y, x,y)*`).

Both studied references draw the same curve with this one reader. Multator's emitter *is* `smooth`. Tonio's ran the same chain a point out of phase, so the Tonio brush repeats its first point when it lays a stroke down, and the reader then reproduces `Tool.Curve` command for command — except at one place.

**The one deviation.** Tonio's `Curve` nudged a segment by `+0.01` where two consecutive points coincided, so its own emitter would not divide by zero. Its endpoint sentinel guarantees exactly that at the end of every line, so the reference curve stops `0.005` units short of its own last point. The shared reader has no such need and lands on the point itself. The gap is `0.01` document units of control point and `0.005` of endpoint — 1/800 of a logical pixel — and it is the only difference from the reference. Raster signatures are unchanged; the parity tests assert the whole command stream inside that tolerance and exact equality everywhere else.

Golden command tests are the geometry authority. Representative DPR=1 software-raster signatures guard broad pixel changes. Unlike original Tonio, toonop deliberately folds device pixel ratio into the Canvas transform; on DPR>1 this produces a sharper raster while logical geometry, widths, compositing, and path commands remain unchanged.

## Brush units

A width, and every threshold a brush thins by, are logical pixels — the same ones on a document of any size. **A pixel is a pixel:** nothing between the slider and the document rescales it, so a brush set to 9 lays a nine-pixel line in a 640-wide document and in a 1920-wide one. Other document sizes are coming; the number on the slider is what will land in each of them, rather than the same share of the picture. The only thing between the width and the screen is the view — the sheet's fit and the zoom — which is also what the cursor ring and the mega eraser's swath measure through, so the three cannot disagree.

A brush reproducing an editor that drew on a canvas of another size brings its numbers over once, where it declares them. The Multator line multiplies the reference's by `1280 / 600 = 2.13(3)`, the ratio of that canvas to the one this editor opens at: the slider 1–300 becomes 1–640, the default 4 becomes 9, the row of dots 2/4/6/10/20 becomes 4/9/13/21/43, and the `+`/`-` ladder 1/5/10 at 10/50 becomes 2/10/20 at 20/100. **The numbers a slider shows are rounded, and that is the one place a reference number is not reproduced.** The thresholds nobody sees come over exactly: the Lang tolerance 10 px becomes 64/3, the old pen's 5 px becomes 32/3. Parity is then checked where it means something — the same picture drawn at this canvas's scale gives the reference's own points, and Lang thins on distances, so the stretch and the tolerance move together.

## Layers

A document frame is the composite of its visible layers, bottom-up (`layers[] → frames[] → strokes[]`, up to 20 layers, every layer the same length). Each layer rasterizes into its own transparent buffer before it lands on the target, so `eraser` and `contour-eraser` cut the alpha of their own layer only — the layer below shows through instead of the background. That is the single eraser path now: the former opaque "eraser paints the background color" branch is gone, so thumbnails, player, GIF and the WebP preview all erase the same way the canvas does. A `hidden` layer is skipped everywhere it could appear (canvas, timeline thumbnails, player, GIF, preview); a single-layer frame without erasers still draws straight into the target, pixel-identical to the composited path.

The shared fixture corpus is the parity contract between the TS and Rust validators, and both agree on every fixture. That includes number spelling: `1e2`, `100.0` and `100` are one JSON number, so both implementations canonicalize them to the same bytes and accept them alike — the editor cannot tell them apart after `JSON.parse`, and the server folds an integer-valued float back before its typed parse. The editor's own serializer never emits a float spelling anyway.

The format carries no layer name — the panel numbers rows by position, top-down. There is one schema version and no migration chain: a document written by an older build is refused with `unsupported-version` rather than lifted, which is what the owner chose while the format was still being shaped.

Onion skin shows the neighbor cells of the **active layer** only, so a static background is not drawn twice. The Multator preset's active-frame alpha (0.8) applies to the whole composited frame, not per layer.

## Canvas viewport

The canvas is a sheet on a table, not a window with a document wedged into it: zoom runs 0.1–10 and the pan is free. A notch of the wheel is 0.5 above 100% and 0.1 below it, so the way back down to a whole page is not a cliff. Both live in `src/lib/ui/viewport.ts` as pure math over CSS pixels and reach the renderer through the optional `panX`/`panY` of `Viewport`: the layer buffers stay the size of the visible canvas, so a 10× zoom costs no extra memory. Thumbnails, player and export never pass a pan and render at 100%, unchanged. Panning is the middle button, space with a drag, or two fingers (pinch zooms too — the reference has no pinch, but the editor is mobile-first); a second finger never interrupts a stroke already under way. The Tonio threshold follows the reference's `_line.m / toonio.drawWindow.scale`: the zoom is frozen on `pointerdown` alongside the rest of the stroke settings, so mid-gesture zooming cannot change the geometry, and at zoom 1 the committed points are bit-identical to before.

## Feather, pixel and the mega eraser

The feather is the pencil's midpoint curve filled with its second colour before being stroked with the first (`tools.js` Feather.PostDraw), so its descriptor carries both. It declares no rules of its own: the curve under it is whichever brush the preset named, so a feather on the Multator panel is collected and thinned the Multator way and read back through the same `smooth` reader.

The pixel tool does declare its own, and they travel in the shipped plugin with the rest of the parity work. It stores grid cells — `w * ~~(v / w)`, dedup against the cells the line already had, thinning by the tool width with no endpoint sentinel — and the renderer fills each cell as a square, Bresenham-filling the cells a fast drag skipped, so a `.toon` import of sparse cells draws right. Its marks are its own on purpose: another brush's smoothing would bend a row of cells into a line, and the smoothing pair never reaches it (`smoothing: false`). The mega eraser knows that from the primitive, not from the name — a stamp is cut by cells (`cut: 'cells'`), a line by pieces.

The mega eraser is not a tool descriptor at all: like the reference it saves nothing, it cuts. `src/lib/tools/mega-eraser.ts` sweeps the gesture capsule (radius = width / 2) over the cell's strokes and rewrites the list with the surviving pieces, each keeping the descriptor of the stroke it came from. Unlike the reference, which lost that work for good, the cut is undoable: `EditorState.erases` keeps the previous stroke list and undo restores it once the cell is back in the state the cut left it.

## Transform tools

The reference's four helper tools (`Drag`, `Lasso`, `Distort`, `Mirror` in `toonio.bundle.js`) are operations over a cell's stroke geometry, not stroke kinds — the document format does not change, the result is ordinary strokes. The maths is `src/lib/model/geom.ts` (affine matrix about a centre, even-odd `pointInPolygon`, bilinear warp, int16 clamp) and the writes are `transformStrokes` / `mirrorCell` / `distortStrokes` in `model/operations.ts`, which round every coordinate back into the stored range.

The hand (`D` / `O`) pans the canvas and opens a zoom window with a thumbnail of the frame, the visible region marked on it, and a slider and field over the same range the wheel steps through. The lasso (`Q` / `S`) takes every stroke with at least one point inside the polygon — the reference's forgiving rule: a stroke the lasso clips comes along whole rather than being cut — and opens a transform over their bounding box. The distort tool (`~`) traces the same polygon and then drags the four corners of that box independently, reprojecting the points bilinearly. `H` and `Shift+H` mirror: the selection while one is live, otherwise the whole cell about the canvas centre.

A transform is a session, not a series of edits: the accumulated `dx/dy/rotate/scaleX/scaleY` (or the dragged quad) lives in `EditorState.transform` and the document is only written on apply. So `Esc` costs nothing and leaves no undo entry, and `Enter` is one step on the same snapshot stack the mega eraser and the timeline paste use. Every path writes through `setTransform`, which is also where the window's own step-back history is recorded. While a session is open its strokes are left out of the layer buffer and drawn moved on top, so a drag never smears over the originals. The canvas handles every gesture itself and the frame, the polygon and the handles are a `pointer-events: none` SVG overlay — touch and pointer capture keep working, and the keyboard path (arrows 1/10, `Q`/`W` rotate, `+`/`-` scale, plus the numeric fields) satisfies WCAG 2.5.7 without a drag. With "change width with scale" on, the tool width is multiplied by the mean of the unsigned axis scales — a mirror is not a thinner line — and clamped to the format's range.

Changing frame, layer or tool applies an unfinished transform the way the reference's `ApplyTransformFast` does; `EditorState.transformLock` is the reference's "paranoid mode", which blocks the move until you apply or drop it instead. Two deliberate deviations: the reference's `MagicWand` is dead code with no button and is not ported, and the distort tool shares the lasso's polygon rather than requiring a separate selection step.

## Importing `.toon`

`src/lib/format/toon-decode.ts` reads Tonio's binary files (v5 plus the legacy 1–4 shapes) into a document the editor's own validator accepts; `TOON_IMPORTER.md` has the layout and the decisions. Imported geometry is never re-prepared — the points in a file are already smoothed and thinned, so they go in as they are (×8 into fixed point), laid down the way the Tonio brush lays a stroke (first point repeated) and read back by the shared `smooth` reader.

## Preset UX profiles

Beyond the line its brush draws, each preset owns a UX profile. Only the editor's own `toonop` lives in `src/lib/ui/ux-profile.ts`; `multator` and `toonio` arrive in the shipped plugin with their brushes, and the editor reads them out of the register without naming either. `multator` reproduces the reference editor end to end: black/red quick palette with the full picker and pipette behind `M`, white = eraser, adaptive `+`/`-` steps (2/10/20, cap 640 — the reference's 1/5/10 and 300 on the editor's canvas), onion skin of the two previous frames only, active frame composited at 0.8 (its `containerSprite.alpha`), delete selects the previous frame, `Ctrl`+add inserts before, playback starts from frame 1 and returns to the edited frame, 5 fps default (30 fps stage ÷ 6). `toonio` reproduces the reference toonio.ru editor: the onion skin is built from the last three *visited* frames rather than the neighbors (`0.15 / history.length * (i + 1)`, bundle:426/437), the palette is the reference's 30-color grid capped at 50 (`defaultPalette`, `paletteLimit`), the pipette previews the color it would take in a 25px swatch throttled to 100 ms and its button opens the native `EyeDropper` on a second click, fps runs 1–30 (`editor.html:270`), the brush goes to 500 and the cursor grows a crosshair below 3 px and at 25 px and up (`tools.js` DrawCursor). One deliberate deviation: the reference toggles the onion on `Tab`, which is the only way a keyboard user leaves the canvas — we bind `K` instead. `toonop` keeps the editor's own behavior. Out of scope: the server save form and the contest `frameLimit`/`disableCopy` flags.

There is one arrangement, not a layout per profile: the reference's workplace (`editor.html`) is what the editor lays out for everyone — tools in two columns on the left with undo/redo, full screen and the drafts list, canvas in the middle, palette box and brush box on the right, timeline and transport below. A preset brings a patch on it, and Multator's is the reference's small editor: everything under the canvas in three rows, two colour squares instead of the palette box, the row of dots instead of the sliders, and none of the keys it never had. The brush box carries a width slider over the brush's own range (1–500 for the Tonio line, 1–640 for the Multator one) and two smoothing sliders (min. distance 0–30, smoothing 1–100) shown only for a brush those two numbers reach, which is why smoothing left the "Configure panel" sheet. Anything placed by hand stays where it was put: a preset patches the arrangement, it does not own it.

The palette box is the reference's `Palette`/`PalettePreview`: large outline and fill swatches with a label, a `+` and a swap between them, then a 35px gapless grid where the left button takes the outline and the right button the fill (`Enter` / `Shift+Enter` from the keyboard), the selected cell carrying a pencil/pen mark; picking a color off the eraser switches back to the pencil, and both the in-canvas pipette and the native `EyeDropper` drop what they take into the grid (`paletteAutoAdd`). Saved palettes live in `toon-editor:saved-palettes` with the reference's `toonio_saved_palettes` fields: a tile list of "Default" plus your own, save-current-under-a-name, and a preview offering load (confirmed), merge (reporting the colors that did not fit `PALETTE_LIMIT`) and delete. Edit mode deletes single colors or clears the grid behind a confirmation. Keys follow the reference: `A` frame, `Shift+A` layer, `Delete` frame, `Shift+Delete` layer, `J`/`L`, `←`/`→` across frames with wraparound, `↑`/`↓` across layers, `Alt+E` mega eraser, `F` the pen.

The big swatches open the reference's own picker (`ColourPicker`, bundle:9810, markup `#colour_picker`) rather than the platform's `input type=color`: a 176×176 surface over a 176×31 bar, three models (HSV, RGB and the colour wheel, labelled as such), R/G/B and hex fields, and a "new / original" preview whose original half puts the colour back. The maths is `color-model.ts` (HSV↔RGB↔hex on integer channels, reversible to within 1 per channel; the hex field takes 3 or 6 digits with or without the `#`) and the geometry `picker-model.ts`, which states each model as one surface plus one bar in 0..1 pointer units — hsv: saturation × value over hue, rgb: blue × green over red, wheel: hue by angle and saturation by radius over value. Both canvases are filled per pixel through that mapping, so a model is a table entry rather than a drawing routine; only the hue strip is painted at full saturation and value (`barPointer`), since reading it off a dark or grey surface would leave it black. Arrows move the surface one axis unit, `Shift` ten, and `Alt` drives the bar instead; the surface is a `role="slider"` and the fields are the text equivalent of it. The window drags by its header, `Esc` or a click outside closes it keeping the current colour, and `Tab` cycles inside. The colour applies live but reaches the grid once, on close, under `paletteAutoAdd`. A preset that places no palette box — Multator, with its two squares — keeps the native input.

## Timeline

The timeline is the reference's (`Timeline`, bundle:8645, `MouseDown` 8894): the shared layer list on the left — the reference's row (eye, name, `⇕`, `×`, every control acting on its own row) under an «+ Слой» header rather than a footer; the drag ends on a window release, because reordering moves the handle's own node and drops its pointer capture — and a layer-by-frame grid of cell thumbnails on the right. The divider lives on the top edge of the bottom panel and resizes the *panel* (151px to 75vh, kept in the UI config as `panelHeight`). It is the reference's `#resizer` — a 16px band sitting `top: -8px`, half of it over the canvas, so the grab target is not the 1px border — and, as the reference does on `.draw`, the editor sets `user-select: none` so a resize never smears a selection across the chrome (the fields you type in keep theirs). The floor is the panel's own chrome plus a timeline showing exactly one layer row; further layers scroll. The timeline is the row that takes whatever height is left, so dragging the bar down hands the grid more layers and frames instead of spreading the buttons out. On a phone the stored height is ignored: the panel sizes itself to its contents, the timeline to its rows capped at 40vh, and the divider goes away. There is no layers popup beside it, which would be a second copy of the same list, and add/delete frame sit on the transport after the frame keys, as on the reference bar.

A click picks the cell's frame *and* layer. `Shift` spans the rectangle from the active cell to the clicked one, `Ctrl` adds or removes a single layer, and `Shift` with the arrows is the keyboard form of the Shift+click; `frame-selection.ts` holds that math. Four states share the grid, and each is a border shape rather than a colour, so none of them depends on hue (WCAG 1.4.1): the active cell a solid ring, the selection a dashed one, the copied block a dotted one, and onion frames a dotted underline under their number, with the copied block also marked `⧉` there.

`C` copies the selected cells with their relative offsets, `V` replaces the cells the buffer lands on from the active one, and `M` adds the buffer's strokes on top of what those cells already hold (`copyCells`/`replaceCells`/`mergeCells`). The block hangs from the active cell, which takes the buffer's first frame and its *top* layer: frames run forward, layers run downward the way the grid shows them, which is toward the lower indices the format stores them under. The target is clipped at the document edges, so a paste near the last frame writes what fits and one near the bottom layer keeps the buffer's top rows and drops what would fall off. `V` and `M` are both one undo step: the cells' previous contents go on a snapshot stack that also carries the mega-eraser cut, and undo restores the whole block as long as every cell is still exactly as the edit left it. Under the Multator preset `M` stays the palette toggle — its only way to the full colour picker — and copy/paste act on whole frames, the keys the reference had.

## Oldschool pen (the reference's "old" easter egg)

The reference hid this pen behind three typed keys and kept it as a flag on the session (Main.hx `lastThreeKeys` → DrawField.hx `onOldEndDraw`). Here it is a brush type picked in the brush box beside thickness and smoothing, and the keys `o`, `l`, `d` do nothing: a type is a pair of brushes of the register (pen and eraser), so the tool in hand keeps its key, its place on the panel and its width record.

The gesture is captured like a Multator line, but the commit runs Lang 5/(32/3) logical px — the reference's 5 px of its own canvas — and traces a closed contour around the polyline at radius `trunc(size/2)` with a random wobble on gentle bends (`src/core-plugin/oldschool-geometry.ts`), stored under the tool kinds `contour` (colour) / `contour-eraser` (reference `action=4, size=0`). The renderer fills it as a closed midpoint chain (`emitGeometry(points, 'smooth', true, …)`, reference `multicurve(..., true)`); the eraser variant punches alpha. The wobble's own clamp (2..6) is read on the already normalised half width, that is, in pixels of the document — it always was, and one canvas under every brush is what makes that right rather than an oversight. One deliberate fix over the port: a click without movement gives the 8-point circle the reference intended (its dot flag was never set).

## Settings

The reference's settings window (`index.html #settings`) is `SettingsSheet.svelte`, a native `<dialog>` — `showModal()` is where the focus trap, `Esc` and the inert page behind it come from. Its options live in the UI config (`toon-editor:ui`, key `settings`) beside the toolbar features, are applied the moment they change, and fall back to the reference defaults one by one when the stored config is damaged.

Drawing: `mouseMode` is the reference's `oldPen` — one point per pointer event, the coalesced batch left unopened, which is what a mouse gives anyway (the brush decides what to do with the samples; the canvas only stops unpacking them); `crossCursor` gates the crosshair the Tonio profile draws at thin and thick widths (the preset still decides whether there is one at all); `lockTransform` is the reference's paranoid mode, `EditorState.transformLock`.

Palette: `paletteAutoAdd` is what a pipette or picker pick obeys before it joins the grid, and `paletteLimit` (30–300 by 10, default 50) is the grid's capacity — `addPaletteColor` is a ring, so at the limit the colour at the start makes room and lowering the limit lets new colours replace the old ones from the beginning. Saved palettes export to and import from the reference's `palettes.json`; an imported palette is renumbered rather than allowed to shadow one already saved, entries without an id and colours that are not `#rrggbb` are dropped, and the sheet reports how many landed.

Autosave: `autosaveMs` runs 10 s … 1 h plus "never" (default a minute, as the reference), and it is a clock rather than a trailing debounce — with a minute-long interval a hand that keeps drawing would reset a debounce forever and never write anything. A write waits out playback, `Ctrl+S` and the sheet write immediately, and the panel shows «Сохранено HH:MM». "Never" leaves the timer unarmed, so `Ctrl+S` is the only way to disk. All drafts export to one file and come back from it with new ids where they would collide. `showDraftsOnStart` decides whether the drafts list greets you.

View: the reference's dark room (`N`, with its grey worktable) is out of parity — the studio carries no theme of its own, because dark is the whole site's business, not the editor's. The reference's background illustrations are out of scope too.

Keys: `Space` runs and stops the preview, and applies an unfinished transform instead when one is open; `Ctrl+S` saves the draft now; `Alt+S` opens the export; `Alt+Enter` mutes the deletion confirmations for the session (deliberately not persisted). These three modified keys fire from a form field too — the browser would otherwise take `Ctrl+S` for "save page" — while every bare key stays out of one. Hovering a button that has a key shows the key in place of its icon (reference `.control p`), drawn over the icon so nothing reflows; the same key is in the `title` and the `aria-label`, and a touch screen skips the swap, where a "hover" sticks after a tap.

## Soundtrack and video export

The reference attaches a track with the note button on the ribbon (`AddAudioClick`), draws its wave on the timeline, plays it with the frames, asks for a name and an author at publish time (`editor_help.js ShowSoundName`) and exports mp4 through Mediabunny with a 26 MB ffmpeg.wasm fallback. Ours does the same work with the platform's own parts.

The track (`src/lib/audio/`) is an mp3, ogg or wav up to 10 MB, checked by `checkAudioFile` and decoded once through an `AudioContext` into a loudness envelope at 200 levels per second. The samples are dropped right after that decode — a 10 MB mp3 is tens of MB of `Float32Array` — and the strip's bars are recomputed from the envelope by `waveformPeaks` whenever fps changes, so switching 12 → 24 stretches the wave over twice as many frames without touching the file. One bar per frame means the wave is exactly as long as the animation: a track that outruns the frames simply has no strip left to draw on. The note button, the name and author fields and the delete button sit under the timeline.

The timeline carries the wave and nothing else. Everything the track *is* — the file, its name, its author, the bin — lives in `AudioPanel.svelte`, a floating plate on the note key beside export (plate on desktop, bottom drawer on a phone). A row of fields under the frames was in the way of the frames, and the panel's floor only has to grow by the lane.

With one bar per frame the wave is exactly as long as the animation: a three-minute track over five frames shows its first fifth of a second. That is honest but says nothing on its own, so the panel names both lengths («Мультик 0:05, трек 3:24») and adds a line when the track outruns the film, and the lane is drawn even where the track is silent.

The reference's synchronisation flag (`editor_help.js ShowSoundName`) is a switch in that panel, kept in the draft and carried to the publication. Tied — the default, and how every track behaved before the flag — the animation is the timeline and the track is pinned to its first frame: frame 0 always means second 0 of the track, and when the animation comes back round the track comes back with it, however much of it was left. A track longer than the animation is heard only as far as the animation reaches; a track shorter than it plays once and the rest of the pass is quiet, then it starts again. In between, the frame is read off the track's own clock rather than counted alongside it, so the two cannot drift. Untied, the frames keep their own clock and the track loops underneath from its own start, which is what background music of an unrelated length wants. A track stored or published without the flag reads as tied.

The loop point being the animation's is why a tied track's element must not `loop` on its own: a track shorter than the animation would otherwise drag the frames back to the start with it and the tail would never show. The restart is checked once per animation frame, so the track can run up to one frame past the loop point before it snaps back — less than the video frame it sits under.

That choice also decides what an export is. The file is what the preview sounds like: tied, the video is one pass of the animation with the track pinned to it; untied, the track sets the length and the animation loops to fill it, so a long song is not cut off at half a second of video. The export sheet says which of the two it is about to do. And the share player can be stepped a frame at a time with the track following, so frame N is heard exactly where it falls — which is how the tie is checked by hand.

Playback rides a plain `<audio>` element rather than an audio graph. Whether it loops on its own is the tie: untied it does, because the frames do and a shorter track would otherwise leave every pass after the first silent; tied it must not, or the tail of a long pass would hear the beginning of the track again, so the animation's own loop restarts it. While it sounds it *is* the clock: `PlayControls` reads the frame off `currentTime` instead of counting alongside it, so picture and sound cannot drift however long the loop runs (the `LoopPlayer` keeps counting underneath and takes over when the track ends). Starting the preview on frame 24 at 12 fps seeks the track to 2.000 s. Stepping through frames without previewing never makes a sound.

The track lives in the draft, not in the document: the toon format holds drawings. `setDraftAudio` writes it on its own, so an autosave never carries a 10 MB blob, and `setDraftCredits` writes a renamed track without the file — reading the name in the effect that writes the blob meant megabytes into IndexedDB per keystroke. Draft writes are queued behind one another: the autosave clock and the track effect are independent, and two read-modify-writes overlapping each read the record before the other's put, so a saved document could drop a freshly attached track or leave the one before it in place. The queue also keeps one connection open at a time, so a finished call never closes the database another is mid-transaction on. Opening a draft writes nothing at all: a restored track and its restored credits are already on disk, so the effects that persist them skip a blob and a name they did not change. Writing them back cost megabytes of IndexedDB traffic a second or two after the draft opened — exactly when the preview is starting — and re-`put`ting the very Blob the playing `<audio>` element reads through an object URL is asking the browser to swap the file out from under it. The size a track was attached at is stored beside it and checked on the way back — a file that returns short is named as damaged rather than handed over as a few seconds of a three-minute song. The drafts export file leaves tracks out entirely: JSON carries no `Blob`, and a file of base64 mp3s would be unusable.

Video export (`src/lib/export/video.ts`) is `MediaRecorder` over `canvas.captureStream()` — no muxer library and no ffmpeg.wasm, which PRODUCT.md's device floor rules out. The browser already encodes off the main thread, already accepts the soundtrack as a second track, and already writes both containers. Which codecs it accepts, though, is not the same anywhere, and the export asks for each container by several names, best first: Chrome and Safari record H.264 into mp4, Chrome and Firefox record VP9 or VP8 into WebM. Two rules come from measurement, not from the specification. mp4 with a soundtrack is offered only where AAC records — Chrome has it where the platform provides an encoder, and on Linux it does not, where an mp4 would otherwise be written with Opus inside that a phone will not play; a silent mp4 names no audio codec and records there anyway. And a silent WebM names no audio codec either, because Firefox hangs on a recorder promised Opus by a stream carrying no audio track. The export sheet offers only what `MediaRecorder.isTypeSupported` confirms, and says in words why mp4 is missing rather than showing a dead control. Frames go through the same `Canvas2DFrameRenderer` as the canvas, the GIF and the player; the watermark is a corner stamp drawn after the frame. A deliberate deviation from the reference: because `MediaRecorder` stamps frames by the wall clock, the export runs in real time — the sheet says how long it will take, and cancelling mid-run aborts the recording and saves nothing. The upgrade path, if that ever grates, is `VideoEncoder` plus a muxer.

The preview loop survives its own accidents. A throw inside one frame no longer ends it — the next frame is scheduled whatever happened — because a dead loop left the frames frozen, the key still reading «Остановить» and only a reload able to bring playback back. `editor.playing` outlives the transport component, so a set flag with no loop behind it counts as stopped and the key starts playback again rather than stopping nothing. And a long track that finishes decoding while the preview is already running joins it at the frame on screen, instead of leaving the whole session silent because play was pressed a moment too early.

Sound is the one thing a browser is entitled to refuse, so no failure here is silent. In the editor a refused `play()`, a file the media element will not take (`decodeAudioData` and the element are different decoders) and an oversized or wrong-typed pick all land in the same line beside the note button. On the share page a publication with sound does not autoplay at all — every browser blocks audio the visitor did not ask for, and a picture looping silently beside a muted track reads as "this animation has none" — so it waits on the play key, which starts both at once; if a play is refused anyway the player stops rather than pretending.

A published track travels beside the document: `POST /a/:id/audio?name=&author=` with the raw file, owner-only and set-once on the same terms as the gallery preview, with the container identified by its magic rather than by any header the client sends. The share page credits the track under the byline and hands `Player` an `audioSrc`, which drives its frames the same way the editor's does.
