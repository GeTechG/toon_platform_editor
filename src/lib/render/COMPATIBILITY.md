# Drawing compatibility rendering

Both saved dialects use fixed-point document coordinates (`1 logical px = 8 units`) and are dispatched only from the saved tool descriptor.

- `multator` keeps toonop's original midpoint emitter and dot-as-filled-circle behavior.
- `toonio` ports `Tool.Curve` from the studied Tonio source: it consumes the duplicated endpoint sentinel, emits midpoint quadratics without re-running input preparation, and applies the `+0.01` coincident-point workaround.

Golden command tests are the geometry authority. Representative DPR=1 software-raster signatures guard broad pixel changes. Unlike original Tonio, toonop deliberately folds device pixel ratio into the Canvas transform; on DPR>1 this produces a sharper raster while logical geometry, widths, compositing, and path commands remain unchanged.

## Layers

A document frame is the composite of its visible layers, bottom-up (`schema_version: 3`, `layers[] → frames[] → strokes[]`, up to 20 layers, every layer the same length). Each layer rasterizes into its own transparent buffer before it lands on the target, so `eraser` and `contour-eraser` cut the alpha of their own layer only — the layer below shows through instead of the background. That is the single eraser path now: the former opaque "eraser paints the background color" branch is gone, so thumbnails, player, GIF and the WebP preview all erase the same way the canvas does. A `hidden` layer is skipped everywhere it could appear (canvas, timeline thumbnails, player, GIF, preview); a single-layer frame without erasers still draws straight into the target, pixel-identical to the composited path.

The shared fixture corpus is the parity contract between the TS and Rust validators, and both agree on every fixture. That includes number spelling: `1e2`, `100.0` and `100` are one JSON number, so both implementations canonicalize them to the same bytes and accept them alike — the editor cannot tell them apart after `JSON.parse`, and the server folds an integer-valued float back before its typed parse. The editor's own serializer never emits a float spelling anyway.

The format carries no layer name — the panel numbers rows by position, top-down. Older documents load through `v1 → v2 → v3`: a v2 document's frames become the cells of one visible layer, strokes and `tool_id`s untouched, and it renders exactly as it did before the migration.

Onion skin shows the neighbor cells of the **active layer** only, so a static background is not drawn twice. The `multator` active-frame alpha (0.8) applies to the whole composited frame, not per layer.

## Canvas viewport

Zoom (1–10, 0.5 per wheel notch) and pan live in `src/lib/ui/viewport.ts` as pure math over CSS pixels and reach the renderer through the optional `panX`/`panY` of `Viewport`: the layer buffers stay the size of the visible canvas, so a 10× zoom costs no extra memory. Thumbnails, player and export never pass a pan and render at 100%, unchanged. Panning is the middle button, space with a drag, or two fingers (pinch zooms too — the reference has no pinch, but the editor is mobile-first); a second finger never interrupts a stroke already under way. The Tonio threshold follows the reference's `_line.m / toonio.drawWindow.scale`: the zoom is frozen on `pointerdown` alongside the rest of the stroke settings, so mid-gesture zooming cannot change the geometry, and at zoom 1 the committed points are bit-identical to before.

## Tonio tools (schema v4)

`feather` and `pixel` join the tool table in `schema_version: 4`; v3 documents lift to it unchanged (the migration is the version bump). The feather is the pencil's midpoint curve filled with its second color before being stroked with the first (`tools.js` Feather.PostDraw), so its descriptor carries both. The pixel tool stores grid cells — `w * ~~(v / w)`, dedup against the cells the line already had, `Prepare` thinning by the tool width with no endpoint sentinel — and the renderer fills each cell as a square, Bresenham-filling the cells a fast drag skipped, so a `.toon` import of sparse cells draws right. Both are Tonio-dialect only, in the schema and in the toolbar.

The mega eraser is not a tool descriptor at all: like the reference it saves nothing, it cuts. `src/lib/tools/mega-eraser.ts` sweeps the gesture capsule (radius = width / 2) over the cell's strokes and rewrites the list with the surviving pieces, each keeping the descriptor of the stroke it came from. Unlike the reference, which lost that work for good, the cut is undoable: `EditorState.erases` keeps the previous stroke list and undo restores it once the cell is back in the state the cut left it.

## Transform tools

The reference's four helper tools (`Drag`, `Lasso`, `Distort`, `Mirror` in `toonio.bundle.js`) are operations over a cell's stroke geometry, not stroke kinds — the document format does not change, the result is ordinary strokes. The maths is `src/lib/model/geom.ts` (affine matrix about a centre, even-odd `pointInPolygon`, bilinear warp, int16 clamp) and the writes are `transformStrokes` / `mirrorCell` / `distortStrokes` in `model/operations.ts`, which round every coordinate back into the stored range.

The hand (`D` / `O`) pans the canvas and opens a zoom window with a thumbnail of the frame, the visible region marked on it, and a slider and field over the same 1–10 range the wheel steps through. The lasso (`Q` / `S`) takes every stroke with at least one point inside the polygon — the reference's forgiving rule: a stroke the lasso clips comes along whole rather than being cut — and opens a transform over their bounding box. The distort tool (`~`) traces the same polygon and then drags the four corners of that box independently, reprojecting the points bilinearly. `H` and `Shift+H` mirror: the selection while one is live, otherwise the whole cell about the canvas centre.

A transform is a session, not a series of edits: the accumulated `dx/dy/rotate/scaleX/scaleY` (or the dragged quad) lives in `EditorState.transform` and the document is only written on apply. So `Esc` costs nothing and leaves no undo entry, and `Enter` is one step on the same snapshot stack the mega eraser and the timeline paste use. Every path writes through `setTransform`, which is also where the window's own step-back history is recorded. While a session is open its strokes are left out of the layer buffer and drawn moved on top, so a drag never smears over the originals. The canvas handles every gesture itself and the frame, the polygon and the handles are a `pointer-events: none` SVG overlay — touch and pointer capture keep working, and the keyboard path (arrows 1/10, `Q`/`W` rotate, `+`/`-` scale, plus the numeric fields) satisfies WCAG 2.5.7 without a drag. With "change width with scale" on, the tool width is multiplied by the mean of the unsigned axis scales — a mirror is not a thinner line — and clamped to the format's range.

Changing frame, layer or tool applies an unfinished transform the way the reference's `ApplyTransformFast` does; `EditorState.transformLock` is the reference's "paranoid mode", which blocks the move until you apply or drop it instead. Two deliberate deviations: the reference's `MagicWand` is dead code with no button and is not ported, and the distort tool shares the lasso's polygon rather than requiring a separate selection step.

## Importing `.toon`

`src/lib/format/toon-decode.ts` reads Tonio's binary files (v5 plus the legacy 1–4 shapes) into a document the editor's own validator accepts; `TOON_IMPORTER.md` has the layout and the decisions. Imported geometry is never re-prepared — the points in a file are already smoothed and thinned, so they go in as they are (×8 into fixed point) and render through the `toonio` dialect.

## Preset UX profiles

Beyond the stroke dialect, each toolbar preset owns a UX profile (`src/lib/ui/ux-profile.ts`). `multator` reproduces the reference editor end to end: black/red quick palette with the full picker and pipette behind `M`, white = eraser, adaptive `+`/`-` steps (1/5/10, cap 300), onion skin of the two previous frames only, active frame composited at 0.8 (its `containerSprite.alpha`), delete selects the previous frame, `Ctrl`+add inserts before, playback starts from frame 1 and returns to the edited frame, 5 fps default (30 fps stage ÷ 6). `toonio` reproduces the reference toonio.ru editor: the onion skin is built from the last three *visited* frames rather than the neighbors (`0.15 / history.length * (i + 1)`, bundle:426/437), the palette is the reference's 30-color grid capped at 50 (`defaultPalette`, `paletteLimit`), the pipette previews the color it would take in a 25px swatch throttled to 100 ms and its button opens the native `EyeDropper` on a second click, fps runs 1–30 (`editor.html:270`), the brush goes to 500 and the cursor grows a crosshair below 3 px and at 25 px and up (`tools.js` DrawCursor). One deliberate deviation: the reference toggles the onion on `Tab`, which is the only way a keyboard user leaves the canvas — we bind `K` instead. `toonop` keeps the editor's own behavior. The layers panel is a preset feature (`layers`): on in Toonop and Toonio, off in Multator; switching to a preset without the panel makes a hidden active layer visible again, since there would be no way back. Out of scope: the server save form and the contest `frameLimit`/`disableCopy` flags.

A profile also owns its `layout`. `bar` (Toonop, Multator) is the one panel under the canvas the editor always had; `toonio` gets `studio`, the reference's workplace (`editor.html`): tools in two columns on the left with undo/redo, full screen and the drafts list, canvas in the middle, palette box and brush box on the right, timeline and transport below. The brush box replaces the dotted widths with a 1–500 slider and two smoothing sliders (min. distance 0–30, smoothing 1–100), which is why smoothing left the "Configure panel" sheet. The transport adds first/previous/next/last frame, an fps slider with its number, and copy/paste frame. On a phone the side columns fold into rows above and below the canvas and the extreme-frame buttons and the fps slider drop out.

The palette box is the reference's `Palette`/`PalettePreview`: large outline and fill swatches with a label, a `+` and a swap between them, then a 35px gapless grid where the left button takes the outline and the right button the fill (`Enter` / `Shift+Enter` from the keyboard), the selected cell carrying a pencil/pen mark; picking a color off the eraser switches back to the pencil, and both the in-canvas pipette and the native `EyeDropper` drop what they take into the grid (`paletteAutoAdd`). Saved palettes live in `toon-editor:saved-palettes` with the reference's `toonio_saved_palettes` fields: a tile list of "Default" plus your own, save-current-under-a-name, and a preview offering load (confirmed), merge (reporting the colors that did not fit `PALETTE_LIMIT`) and delete. Edit mode deletes single colors or clears the grid behind a confirmation. Studio keys follow the reference: `A` frame, `Shift+A` layer, `Delete` frame, `Shift+Delete` layer, `J`/`L`, `←`/`→` across frames with wraparound, `↑`/`↓` across layers, `Alt+E` mega eraser, `F` the pen.

The big swatches open the reference's own picker (`ColourPicker`, bundle:9810, markup `#colour_picker`) rather than the platform's `input type=color`: a 176×176 surface over a 176×31 bar, three models (HSV, RGB and the colour wheel, labelled as such), R/G/B and hex fields, and a "new / original" preview whose original half puts the colour back. The maths is `color-model.ts` (HSV↔RGB↔hex on integer channels, reversible to within 1 per channel; the hex field takes 3 or 6 digits with or without the `#`) and the geometry `picker-model.ts`, which states each model as one surface plus one bar in 0..1 pointer units — hsv: saturation × value over hue, rgb: blue × green over red, wheel: hue by angle and saturation by radius over value. Both canvases are filled per pixel through that mapping, so a model is a table entry rather than a drawing routine; only the hue strip is painted at full saturation and value (`barPointer`), since reading it off a dark or grey surface would leave it black. Arrows move the surface one axis unit, `Shift` ten, and `Alt` drives the bar instead; the surface is a `role="slider"` and the fields are the text equivalent of it. The window drags by its header, `Esc` or a click outside closes it keeping the current colour, and `Tab` cycles inside. The colour applies live but reaches the grid once, on close, under `paletteAutoAdd`. The `bar` layout has no palette box and keeps the native input.

## Studio timeline

The `studio` layout also changes the timeline (reference `Timeline`, bundle:8645, `MouseDown` 8894). `bar` keeps the single strip of frame thumbnails; `studio` splits it into the shared layer list on the left — the same `LayerRows` the popup panel renders, so the two forms cannot drift, with the reference's row (eye, name, `⇕`, `×`, every control acting on its own row) under an «+ Слой» header rather than a footer; the drag ends on a window release, because reordering moves the handle's own node and drops its pointer capture — and a layer-by-frame grid of cell thumbnails on the right. The divider lives on the top edge of the bottom panel and resizes the *panel* (151px to 75vh, kept in the UI config as `panelHeight`). It is the reference's `#resizer` — a 16px band sitting `top: -8px`, half of it over the canvas, so the grab target is not the 1px border — and, as the reference does on `.draw`, the editor sets `user-select: none` so a resize never smears a selection across the chrome (the fields you type in keep theirs). The floor is the panel's own chrome plus a timeline showing exactly one layer row; further layers scroll. The timeline is the row that takes whatever height is left, so dragging the bar down hands the grid more layers and frames instead of spreading the buttons out. On a phone the stored height is ignored: the panel sizes itself to its contents, the timeline to its rows capped at 40vh, and the divider goes away. The studio does not also offer the layers popup, which would be a second copy of the same list, and add/delete frame sit on the transport after the frame keys, as on the reference bar, instead of beside the strip.

A click picks the cell's frame *and* layer. `Shift` spans the rectangle from the active cell to the clicked one, `Ctrl` adds or removes a single layer, and `Shift` with the arrows is the keyboard form of the Shift+click; `frame-selection.ts` holds that math. Four states share the grid, and each is a border shape rather than a colour, so none of them depends on hue (WCAG 1.4.1): the active cell a solid ring, the selection a dashed one, the copied block a dotted one, and onion frames a dotted underline under their number, with the copied block also marked `⧉` there.

`C` copies the selected cells with their relative offsets, `V` replaces the cells the buffer lands on from the active one, and `M` adds the buffer's strokes on top of what those cells already hold (`copyCells`/`replaceCells`/`mergeCells`). The block hangs from the active cell, which takes the buffer's first frame and its *top* layer: frames run forward, layers run downward the way the grid shows them, which is toward the lower indices the format stores them under. The target is clipped at the document edges, so a paste near the last frame writes what fits and one near the bottom layer keeps the buffer's top rows and drops what would fall off. `V` and `M` are both one undo step: the cells' previous contents go on a snapshot stack that also carries the mega-eraser cut, and undo restores the whole block as long as every cell is still exactly as the edit left it. In the `bar` layout there is no selection, so `C`/`V` stay whole-frame copy and paste and `M` stays Multator's palette toggle — its only way to the full color picker.

## Oldschool pen ("old" easter egg)

Typing `o`, `l`, `d` toggles the reference's hidden oldschool pen (Main.hx `lastThreeKeys` → DrawField.hx `onOldEndDraw`). The gesture is captured like a Multator line, but the commit runs Lang 5/5 px and traces a closed contour around the polyline at radius `trunc(size/2)` with a random wobble on gentle bends (`src/lib/tools/oldschool.ts`), stored under the v2 tool kinds `contour` (color) / `contour-eraser` (reference `action=4, size=0`). The renderer fills it as a closed midpoint multicurve (`emitMultatorClosedPath`, reference `multicurve(..., true)`); the eraser variant punches alpha. Tonio strokes ignore the flag. One deliberate fix over the port: a click without movement gives the 8-point circle the reference intended (its dot flag was never set).

## Settings

The reference's settings window (`index.html #settings`) is `SettingsSheet.svelte`, a native `<dialog>` — `showModal()` is where the focus trap, `Esc` and the inert page behind it come from. Its nine options live in the UI config (`toon-editor:ui`, key `settings`) beside the toolbar features, are applied the moment they change, and fall back to the reference defaults one by one when the stored config is damaged.

Drawing: `mouseMode` is the oldschool pen kept on for good, the same flag the "old" easter egg toggles; `crossCursor` gates the crosshair the Tonio profile draws at thin and thick widths (the preset still decides whether there is one at all); `lockTransform` is the reference's paranoid mode, `EditorState.transformLock`.

Palette: `paletteAutoAdd` is what a pipette or picker pick obeys before it joins the grid, and `paletteLimit` (30–300 by 10, default 50) is the grid's capacity — `addPaletteColor` is a ring, so at the limit the colour at the start makes room and lowering the limit lets new colours replace the old ones from the beginning. Saved palettes export to and import from the reference's `palettes.json`; an imported palette is renumbered rather than allowed to shadow one already saved, entries without an id and colours that are not `#rrggbb` are dropped, and the sheet reports how many landed.

Autosave: `autosaveMs` runs 10 s … 1 h plus "never" (default a minute, as the reference), and it is a clock rather than a trailing debounce — with a minute-long interval a hand that keeps drawing would reset a debounce forever and never write anything. A write waits out playback, `Ctrl+S` and the sheet write immediately, and the panel shows «Сохранено HH:MM». "Never" leaves the timer unarmed, so `Ctrl+S` is the only way to disk. All drafts export to one file and come back from it with new ids where they would collide. `showDraftsOnStart` decides whether the drafts list greets you.

View: `theme` is the reference's dark room (`N`) — window `#19191A`, worktable `#262626`, accent `#0D85F3`, as `.editor.dark` token overrides, with the text at 15.7:1 and the accent at 5.9:1 against them (WCAG 1.4.3 / 1.4.11). `greyCanvas` puts the reference's `#616161` under the drawing instead of that near-black. Only the chrome turns dark: the document's own background, the frame thumbnails and the GIF export stay white. The reference's background illustrations and its alternative layout are out of scope.

Keys: `Space` runs and stops the preview, and applies an unfinished transform instead when one is open; `Ctrl+S` saves the draft now; `Alt+S` opens the export; `Alt+Enter` mutes the deletion confirmations for the session (deliberately not persisted); `N` switches the theme. These three modified keys fire from a form field too — the browser would otherwise take `Ctrl+S` for "save page" — while every bare key stays out of one. Hovering a button that has a key shows the key in place of its icon (reference `.control p`), drawn over the icon so nothing reflows; the same key is in the `title` and the `aria-label`, and a touch screen skips the swap, where a "hover" sticks after a tap.

## Soundtrack and video export

The reference attaches a track with the note button on the ribbon (`AddAudioClick`), draws its wave on the timeline, plays it with the frames, asks for a name and an author at publish time (`editor_help.js ShowSoundName`) and exports mp4 through Mediabunny with a 26 MB ffmpeg.wasm fallback. Ours does the same work with the platform's own parts.

The track (`src/lib/audio/`) is an mp3, ogg or wav up to 10 MB, checked by `checkAudioFile` and decoded once through an `AudioContext` into a loudness envelope at 200 levels per second. The samples are dropped right after that decode — a 10 MB mp3 is tens of MB of `Float32Array` — and the strip's bars are recomputed from the envelope by `waveformPeaks` whenever fps changes, so switching 12 → 24 stretches the wave over twice as many frames without touching the file. One bar per frame means the wave is exactly as long as the animation: a track that outruns the frames simply has no strip left to draw on. The note button, the name and author fields and the delete button sit under the timeline in both layouts.

The timeline carries the wave and nothing else. Everything the track *is* — the file, its name, its author, the bin — lives in `AudioPanel.svelte`, a floating plate on the note key beside layers and export, built like the layers popup (plate on desktop, bottom drawer on a phone). A row of fields under the frames was in the way of the frames, and the panel's floor only has to grow by the lane.

With one bar per frame the wave is exactly as long as the animation: a three-minute track over five frames shows its first fifth of a second. That is honest but says nothing on its own, so the panel names both lengths («Мультик 0:05, трек 3:24») and adds a line when the track outruns the film, and the lane is drawn even where the track is silent.

Playback rides a plain `<audio>` element rather than an audio graph. It loops, because the frames do — a track shorter than the animation would otherwise run out part-way through the preview and leave every pass after it silent. While it sounds it *is* the clock: `PlayControls` reads the frame off `currentTime` instead of counting alongside it, so picture and sound cannot drift however long the loop runs (the `LoopPlayer` keeps counting underneath and takes over when the track ends). Starting the preview on frame 24 at 12 fps seeks the track to 2.000 s. Stepping through frames without previewing never makes a sound.

The track lives in the draft, not in the document: the toon format holds drawings. `setDraftAudio` writes it on its own, so an autosave never carries a 10 MB blob, and `setDraftCredits` writes a renamed track without the file — reading the name in the effect that writes the blob meant megabytes into IndexedDB per keystroke. Draft writes are queued behind one another: the autosave clock and the track effect are independent, and two read-modify-writes overlapping each read the record before the other's put, so a saved document could drop a freshly attached track or leave the one before it in place. The queue also keeps one connection open at a time, so a finished call never closes the database another is mid-transaction on. The size a track was attached at is stored beside it and checked on the way back — a file that returns short is named as damaged rather than handed over as a few seconds of a three-minute song. The drafts export file leaves tracks out entirely: JSON carries no `Blob`, and a file of base64 mp3s would be unusable.

Video export (`src/lib/export/video.ts`) is `MediaRecorder` over `canvas.captureStream()` — no muxer library and no ffmpeg.wasm, which PRODUCT.md's device floor rules out. The browser already encodes off the main thread, already accepts the soundtrack as a second track, and already writes both containers: Chromium and Safari record `video/mp4` with H.264 + AAC, Firefox records WebM with VP9 + Opus. The export sheet offers only what `MediaRecorder.isTypeSupported` confirms, and says in words why mp4 is missing rather than showing a dead control. Frames go through the same `Canvas2DFrameRenderer` as the canvas, the GIF and the player; the watermark is a corner stamp drawn after the frame. A deliberate deviation from the reference: because `MediaRecorder` stamps frames by the wall clock, the export runs in real time — the sheet says how long it will take, and cancelling mid-run aborts the recording and saves nothing. The upgrade path, if that ever grates, is `VideoEncoder` plus a muxer.

Sound is the one thing a browser is entitled to refuse, so no failure here is silent. In the editor a refused `play()`, a file the media element will not take (`decodeAudioData` and the element are different decoders) and an oversized or wrong-typed pick all land in the same line beside the note button. On the share page a publication with sound does not autoplay at all — every browser blocks audio the visitor did not ask for, and a picture looping silently beside a muted track reads as "this animation has none" — so it waits on the play key, which starts both at once; if a play is refused anyway the player stops rather than pretending.

A published track travels beside the document: `POST /a/:id/audio?name=&author=` with the raw file, owner-only and set-once on the same terms as the gallery preview, with the container identified by its magic rather than by any header the client sends. The share page credits the track under the byline and hands `Player` an `audioSrc`, which drives its frames the same way the editor's does.
